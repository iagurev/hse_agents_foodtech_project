# Карта репозитория

Актуально на 20 октября 2026. Это навигация по реализованному коду; продуктовые правила и контракты определены в [продукте](../design/product.md), [harness](agent-harness.md) и [HTTP-приложении](web-application.md).

## Точки входа

- `./run.sh` — проверка каталогов, сборка интерфейса и запуск приложения.
- `uv run meal-app` → [`web/server.py`](../../src/app/web/server.py): создание FastAPI, зависимости, HTTP-маршруты и lifespan.
- `uv run python -m app.assistant` → [`assistant/__main__.py`](../../src/app/assistant/__main__.py): терминальный диалог.
- [`frontend/src/main.tsx`](../../frontend/src/main.tsx) — React, пользовательская сессия, hash-навигация и нижние вкладки.
- [`config.py`](../../src/app/config.py) — все прикладные настройки. `.env.example` показывает безопасные примеры; секреты и runtime находятся вне Git.

## Backend

| Где | Ответственность |
|---|---|
| `assistant/agent.py` | Модель, агент и персональные инструкции |
| `assistant/tools.py` | Описание, входная/выходная схема и обработчик каждого tool рядом; единый реестр |
| `assistant/context.py`, `session.py` | Зависимости хода, SDK-цикл, события, сохранение истории и лимиты |
| `assistant/compaction.py`, `tokens.py` | Выбор истории, сводка, отдельный бюджет и подсчёт контекста |
| `assistant/prompts/` | Русские Markdown-промпты, загружаемые ресурсами пакета |
| `planning.py` | Создание/редактирование меню и четыре проверки |
| `shopping/service.py` | Создание/редактирование покупки, кандидаты, выбор модели, ссылки и сохранение |
| `shopping/calculations.py` | Агрегация продуктов, количество упаковок, стоимость, бюджет и сборка результата; без БД, сети и LLM |
| `models.py`, `llm.py` | Общие предметные типы и ограниченные структурированные вызовы модели |
| `catalog.py`, `catalog_check.py` | Чтение трёх каталогов и отдельная офлайн-проверка их согласованности |
| `retrieval/` | Локальный гибридный поиск: сервис, признаки, индекс и encoder |
| `integrations.py`, `network.py` | MCP ВкусВилла и TLS для внешних клиентов |
| `storage.py` | Предметные версии, история, память, квитанции и кэши SQLite |
| `web/storage.py`, `contracts.py` | Аккаунты/сессии/чаты и HTTP-входы; дополняют предметное хранилище |
| `web/runs.py`, `guard.py` | Фоновые ходы, guard, остановка и SSE |
| `web/presentation.py`, `objects.py` | Безопасная проекция для UI и ручные правки без LLM |
| `energy.py`, `progress.py`, `tracing.py` | Ориентир питания, события этапов и Langfuse |

Путь сообщения: `web/server.py` → `web/runs.py` → guard → `assistant/session.py` → агент и tools → предметная операция → сохранение. SSE и загрузка переписки используют одну UI-проекцию. Ручная правка идёт через `web/objects.py` в те же расчёты и версионное хранилище, минуя модель.

## Frontend

| Где в `frontend/src/` | Что искать |
|---|---|
| `screens/Chat.tsx` | Выбор чата, отправка сообщения, подписка SSE, композер и прокрутка |
| `screens/Collections.tsx` | Списки планов/покупок и поиск рецептов |
| `screens/PlanDetail.tsx` | Дни меню, порции, предварительные показатели и сохранение |
| `screens/RecipeDetail.tsx` | Ингредиенты, шаги и масштаб выбранной порции |
| `screens/CartDetail.tsx` | Состав покупки, количества, отметки и ссылки магазина |
| `screens/Profile.tsx` | Общая форма анкеты, регистрация/вход и настройки |
| `components/ChatCards.tsx` | Карточки объектов, выбор рецептов и привязки в сообщениях; карточки переиспользуются коллекциями |
| `components/ResponseStatus.tsx` | Названия этапов и общий таймер ответа |
| `components/ui.tsx` | Нижняя панель, состояния загрузки/ошибки, изображения, КБЖУ и действия с объектом |
| `api.ts`, `preview.ts` | HTTP/типы/форматирование и чистые расчёты черновиков соответственно |
| `styles/` | `styles.css` — оболочка; `forms.css` — формы; `chat.css` — диалог; `objects.css` — планы, рецепты, покупки |

Компоненты экранов владеют состоянием своих форм и загрузки. Общие карточки не отправляют запросы модели самостоятельно: передают поручение в существующий обработчик чата. Новый роутер, хранилище состояния и универсальный слой экранов не нужны.

## Данные, документы и проверки

- `data/` — только `recipes.sqlite`, `products.sqlite`, `sources.sqlite` через Git LFS. Подготовка данных не запускается в диалоге. [Пути и формат](data-storage.md).
- `tests/` — детерминированные проверки по предметным областям. `frontend/test/` — числовые расчёты интерфейса.
- `docs/design/` — продукт и визуальные правила; `docs/technical/` — устройство и контракты; `docs/specs/` — требования и приёмка; `docs/plans/` — планы выполнения.
- `docs/memory/` — краткое текущее состояние, решения и открытые ограничения. История измерений — в [verification](verification.md), [UX-аудите](ux-audit.md) и [аудите каталога](catalog-audit.md).
- `.impeccable/`, сборки, кэши и `.env` — локальные материалы, не часть поставляемого приложения.

Схемы tools намеренно не разделены по файлу на каждый инструмент. SDK-цикл, compaction и транзакции хранилища также сохранены целиком в своих модулях: их ветвления обеспечивают уже согласованное поведение при отмене, повторе и конфликте версий.
