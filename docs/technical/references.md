## Аудит конкретных промптов и компонентов

Аудит 2026-10-18 дополняет общий список ссылок точными файлами и именами инструкций. Ссылка на документацию structured output не считается готовым промптом составления меню. Наличие опубликованного примера с GPT не доказывает качество его предметной адаптации или переноса на GLM.

Уровни свидетельств различаются:

- **Исходник runtime:** реальный шаблон или механизм в открытом коде продукта/библиотеки.
- **Снимок:** выбранный пользователем неофициальный текст; происхождение и качество отдельно не подтверждены.
- **Пример с GPT:** официальный пример с указанной GPT-моделью и конкретными инструкциями; это пример, не production benchmark нашего сценария.
- **Предметная адаптация:** часть выводится из требований приложения и ещё требует собственных испытаний.

Поиск рецептов, получение объектов, агрегация, вычисление КБЖУ/цены, кэш и сохранение результата выполняются кодом и не требуют собственных генеративных промптов. Embedding-запрос не вводит дополнительного агента-ранжировщика. Внутреннее устройство внешнего MCP не считается нашим промптом. Подготовка корпуса рецептов находится вне runtime-аудита: отдельный генеративный процесс для неё пока не утверждён.

### Механизмы, для которых нужен код, а не ещё один prompt

| Механизм | Основание и граница переноса |
| --- | --- |
| Agent loop, Tool/Toolset, зависимости | Штатный SDK, R-TOOLS и R-DEPS; не собственный граф автономных ролей |
| Персональный контекст на каждый run | R-DEPS; отдельный пользователь и чат — наша модель данных |
| История, сериализация, целые ходы, сводка | R-HISTORY, R-SESSION, Codex `normalize.rs`; пороги и хранение сырого журнала задаёт приложение |
| Markdown отдельно от кода | R-COMPACT + `compact.rs`; Python-загрузка по R-RESOURCES — языковая адаптация, не Rust `include_str!` в Python |
| Reasoning и streaming | Provider/SDK-протокол, ссылки ниже; результаты текущего endpoint и проверки стриминга приведены в отчёте |
| Расчёты и четыре проверки плана | Утверждённые требования продукта; их корректность подтверждают тесты, а не происхождение из GPT-harness |
| Кэш, агрегация, повтор доставки, отмена, версии объектов | Прикладные операции и правила целостности данных. Готовым промптом они не покрываются; нужны собственная реализация и проверки |
| Обновление общей memory | Есть модельный интерфейс из снимка; способ хранения, конфликтов и забывания — наша реализация по утверждённому контракту, проверенная тестами |

## Как использовать источники при написании промптов

Для каждого блока нужно сохранить ссылку на файл/commit и раздел, русский текст и кратко указать предметные замены. Это можно вести в этой таблице и истории изменений; отдельный framework для управления промптами не нужен. Сначала переводится подходящий исходный блок, затем явно добавляются требования продукта. Известность репозитория, учебный вывод или наличие работающего примера не заменяют проверку на целевой модели.

В частности, формулировка из снимка Codex о том, что более ранние запросы после сжатия считаются устаревшими, не переносится буквально: она может потерять действующие ограничения пользователя. Состояние задачи и отмена условий должны соответствовать нашей модели диалога. Названия `commentary`/`final` также не становятся каналами GLM.

Нельзя утверждать полное покрытие готовыми проверенными промптами. Основа диалога, сжатие и инфраструктурные механизмы имеют конкретные источники; меню и подбор SKU покрыты аналогиями, но требуют предметной адаптации и испытаний. Произвольный сторонний prompt без сопоставимых контрактов и результатов не закрывает этот пробел.

## GLM и OpenRouter

- [GLM-5.3-Flash model card](https://huggingface.co/zai-org/GLM-5.3-Flash): уровни reasoning `low/high/max`, default `max`; chat-specific рекомендация для `clear_thinking`.
- [Z.ai: GLM-5.3-Flash](https://docs.z.ai/guides/vlm/glm-5.3-flash): параметры прямого API; рекомендации не во всём совпадают с chat-specific model card.
- [Z.ai: Thinking mode](https://docs.z.ai/guides/capabilities/thinking-mode): reasoning в последовательности вызовов инструментов.
- [OpenRouter: Reasoning tokens](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens): сохранение `reasoning_details` в текущем цикле.

Chat template модели при `clear_thinking=true` отделяет reasoning до последнего пользовательского сообщения от reasoning внутри текущего хода. Параметр clear_thinking в OpenRouter не предполагается поддержанным: эквивалентная политика удаления завершённого reasoning реализована при подготовке истории. Похожие ответы моделей не доказывают одинаковый протокол.

## Входы и выходы реализованных промптов

| Файл | Вход | Выход и граница адаптации |
| --- | --- | --- |
| `agent_system_prompt.md` | Контекст пользователя, сводка, история; definitions tools отдельно | Текст или native calls. Смысловой перевод правил общения/действия из выбранного Codex; роль питания, общие условия работы и правила памяти написаны для приложения. Аргументы и расшифровки результатов находятся в descriptions |
| `meal_plan.md` | Каталог, request, days, limits, контекст; candidate/feedback при необходимости | `PlanDraft`: meals, explanation. R-SELECT даёт структуру выбора известных кандидатов и feedback; питание, техника, разнообразие, порции и невозможные условия — наши правила |
| `edit_plan.md` | Весь current_plan, request; candidate/feedback/fixed_limits при коррекции | PlanRevision: все meals, days, limits, explanation. R-EXTRACT/R-SELECT — структурированный ответ и feedback; полная версия, сохранение остальных записей и условия правки — собственная предметная адаптация |
| `edit_cart.md` | Весь current_cart, request, небольшой набор продуктов и явно названные SKU | CartRevision: все products, unresolved, limits; для прямых SKU — SkuCartRevision: items и limits. R-EXTRACT/R-SELECT — форма ограниченного преобразования; сохранение SKU, единицы и бюджет — собственная предметная адаптация |
| `product_selection.md` | Потребности, кандидаты SKU, контекст, request, limits | `Selection`: choices по product_id со sku_id либо null и краткой причиной. Выбор из известных вариантов — R-SELECT; фасовка/количества и непокрытые потребности — наши правила |
| `compact.md` | Прежняя сводка, завершённые ходы, хронологические user_messages и max_summary_tokens | Текстовая сводка до 8000 токенов. Перевод смысла R-COMPACT и структуры R-SESSION; наши объекты, исключения и запрет восстанавливать забытую память |

Точные имена структур и типов находятся в коде; формат задаёт Pydantic, а не повтор JSON Schema в Markdown. Разговорный промпт не требует публиковать подробные рассуждения. В ходе проверок уточнены границы временной памяти, полного каталога, оборудования и завершения частичной корзины; эти уточнения относятся к предметной адаптации, не к исходному Codex.

## Актуальные дополнительные основания

- [OpenAI: latest-model guide](https://developers.openai.com/api/docs/guides/latest-model) — конкретные инструкции, ясные критерии результата и адаптация под модель вместо обязательного подробного reasoning.
- [OpenAI: Rethinking skills and prompts](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra) — узкие инструкции по реальной задаче, проверка результата и отказ от ненужного переноса всего harness.
- [Pydantic AI: Model profiles](https://pydantic.dev/docs/ai/models/overview/) — явный профиль возможностей и штатное преобразование схем; GLM не должна наследовать неподтверждённые ограничения другого endpoint.

Рекомендации для GPT — источник структуры и ясности, а не доказательство идентичного поведения GLM. Проверка на выбранной GLM обязательна и выполнена в ограниченной серии.

### Уточнение границ инструкций, 2026-10-18

- [OpenAI: Function calling, Best practices](https://developers.openai.com/api/docs/guides/function-calling#best-practices-for-defining-functions) допускает правила выбора инструментов в системном промпте и требует ясных определений функций, параметров и результатов. В приложении общий выбор действий остаётся в MD; значения статусов и полей, условия продолжения частичной покупки и ошибки описаны рядом с tools.
- [Anthropic: Effective context engineering, The anatomy of effective context](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) рекомендует прямой язык и конкретные, но не чрезмерно жёсткие инструкции. Предметная адаптация: смысл поручения вместо триггеров по глаголам; заранее разрешённая конкретная замена допускает продолжение partial, одинаковые безрезультатные попытки не повторяются.
- [LangChain: Memory overview, Profile](https://docs.langchain.com/oss/python/concepts/memory#profile) описывает обновляемый профиль на основе прежней редакции и новых сведений. У нас сохраняется свободный текст, не переносится JSON-профиль или новый framework. По решению пользователя покрыты устойчивое изменение, уточнение и пересмотр памяти по просьбе; фоновой очистки и нового механизма забывания нет.

Это основания организации текста, не готовые предметные промпты. Отсутствие рецептов обрабатывается обычным ответом по результату инструмента, без отдельного сценария пополнения базы. Повторные проверки после изменения инструкций отмечаются отдельно в [отчёте](verification.md).

## Основания редакторов полных версий

Редакторы edit_plan.md и edit_cart.md не являются переводами готового промпта редактирования питания. Из R-EXTRACT берётся форма «контекст и поручение → типизированный результат», из R-SELECT/R-FEEDBACK — конкретные замечания и ограниченная коррекция. Полные версии вместо diff, сохранение незатронутых записей и SKU, изменение сохранённых limits только по поручению — прямые требования пользователя. Схемы задаёт Pydantic. Подключение ресурсов использует R-RESOURCES.

Эти основания не доказывают качество новых промптов на GLM. Детерминированные проверки и фактическая доступность живых проб указаны в отчёте; результаты прежних серий не переносятся на новые редакторы автоматически.

Новая живая серия редакторов: семь сценариев, девять модельных запросов; нарушений в этих сценариях не обнаружено. Это ограниченное свидетельство, не универсальная гарантия. Фактические метрики и внешний отказ ссылки — в отчёте.

## Input guard и веб-контекст — 19.10.2026

`src/app/assistant/prompts/input_guard.md` — предметная адаптация проекта по утверждённому scope: опасные запросы и вмешательство в инструкции, без фильтра темы питания. Текст политики не объявляется переводом системного промпта OpenAI или доказанным защитным барьером; проверка двух разрешённых живых запросов не заменяет проверку качества классификации.
