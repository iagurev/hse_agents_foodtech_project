Пользователь разрешил справочное КБЖУ простых продуктов с явным происхождением; цена по-прежнему берётся только из товаров. Числа 826/4701 ниже относятся к исходному продуктовому этапу, 825/4695 — к последующей [очистке для RAG](catalog-rag-readiness.md).

JSON/JSONL, отчёты и команды подготовки ниже относятся к архиву `../hse_agents_data_archive/2026-10-19/`; выполнять их следует только в согласованном архивном снимке кода. ## Правила

Общий продукт строится снизу вверх из пищевых SKU. Названия рецептов не создают новые общие продукты. Бренды, сорта яблок, фасовки и жирность обычного творога не создают отдельные продукты. Сладкие десерты не входят в обычный творог; пшеничная и рисовая мука, свежие и сушёные фрукты, сырые и приготовленные компоненты разделены. Архивные связи служат предложениями и проверяются по имени, категории, состоянию и составу карточки.

Для твёрдых продуктов базовая единица g, база 100. Для жидкостей единица выбирается по подтверждённым данным; масса и объём не приравниваются. Существующие записи с используемой в сохранённых объектах другой единицей остаются совместимыми, а не получают новый смысл количества. Исправление единиц не меняет численные количества сохранённых рецептов без подтверждённой конверсии.

Каждый SKU учитывается один раз. Цена приводится к базе из явной фасовки или цены за кг; массовый placeholder 1 кг не считается фасовкой. Средняя цена — среднее нормализованных наблюдений, min/max — фактический диапазон. КБЖУ — средние исходных маркировок подходящих товаров на той же базе; известные варианты поставщиков учитываются с явным происхождением. Средние категории являются расчётом по наблюдениям, а не обещанием состава любого SKU. Отсутствующее значение не подменяется нулём; ноль допустим только из явной маркировки либо доказуемого состава.

Исходный MCP JSON сохраняется без изменения. Список product↔SKU, причины исключения, источники величин, размеры выборок и диапазоны сохраняются в отдельном справочном артефакте и доступны приложению. Беспричинное полное совпадение названий больше не требуется.

Публичный справочник очищается от прежних прототипов по названиям рецептов. Перед миграцией выполняются backup и проверка ссылок; готовые рецепты, объекты и история сохраняются. Несопоставленные исходные записи остаются в отчёте; отсутствующие в исходнике показатели не выдумываются.

## Результат и границы

После полной очистки [catalog-cleanup](catalog-cleanup.md) рабочая БД содержит **826 полных категорий и 4701 принятую связь product↔SKU**. 822 категории используют g, четыре — ml. Служебные записи для четырёх прежних рецептов скрыты из нового поиска и не используются новыми адаптациями.

Все **7492** MCP-карточки сохранены неизменными. Из них 5401 SKU распределены по 1055 существующим категориям, 1536 непищевых исключены, **555** оставлены неразрешёнными (440 требуют проверки, 115 не имеют подходящей существующей категории). **229 категорий неполные**: у 160 нет подтверждённого полного КБЖУ, у 73 нет совместимой цены, четыре входят в обе группы. Неполные категории остаются в evidence/pending и не входят в рабочий поиск.

Пересмотрены все SKU, затем весь состав полученных категорий с полными описаниями, составом и отделами магазина. Изменились 1300 сопоставлений; 744 SKU перенесены между существующими категориями. Отдельная сверка буквальных имён устранила несовпадения модельных числовых ссылок с объяснением. Агрегаты используют только принятые вторым проходом SKU. Это сохранённый многоэтапный предметный контроль с защитными правилами, а не гарантия ручной экспертизы каждого товара.

Свежая клубника больше не включает пюре с сахаром; обычные шоколад, сгущёнка и сливочный сыр не включают несовместимые наполнители/виды обработки. Две грудки, приготовленные sous-vide по описанию, перенесены из сырого мяса. Недостаток маркировки после исключения несовместимого SKU не компенсируется догадкой. Неполные сырые картофель/лук и некоторые масла остаются неполными; готовые картофель/лук и топлёное масло — самостоятельные типы.

Дополнения прежнего сбора сохранены: проверены страницы 1102 SKU, подтверждены 1002 фасовки и 628 маркировок. Их числа применяются только к тем товарам, которые прошли новую проверку членства. Модель не генерирует маркировку или цены.

Примеры из рабочего каталога, **на 100 г**:

| Продукт | SKU в категории | Средняя цена, руб. | ккал | Белки, г | Жиры, г | Углеводы, г |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Творог | 37 | 63,93 | 119,44 | 14,18 | 5,69 | 2,82 |
| Яблоко | 17 | 19,74 | 52 | 0,3 | 0,2 | 14 |
| Мука | 8 | 9,47 | 342 | 12,05 | 1,225 | 70,68 |

Это средние категории. Цены относятся к снимку **17.10.2026**, фасовки дополнены страницами того же SKU. Число наблюдений цены и КБЖУ может быть меньше числа связанных SKU; отдельно сохранены выборки и диапазоны. КБЖУ творога и муки — агрегаты маркировок; яблока — [справочные данные журнала ВкусВилла](https://vkusvill.ru/media/journal/polza-yablok-skolko-sedat-v-den-kakie-yabloki-luchshie-otvechaem-na-chastye-voprosy.html). Для банана сохранён полный текст индексированной официальной карточки 116954: текущий URL возвращает 404, это отмечено в происхождении. Для простой воды и соли сохранено отдельное доказательство нулевого КБЖУ по неэнергетическому минеральному составу; это правило не применяется к кокосовой/ароматизированной воде или соли с пряностями.

Твёрдые категории используют g. Молоко и сливки также имеют каноническую массу: их маркировка дана на 100 г, цена рассчитана по товарам с явной массой. Плотность не угадывается. Прежнее молоко в ml осталось только служебной записью для сохранённых количеств. Картофель нормализован в g и пока находится в доработке из-за отсутствия полного КБЖУ; фри не подставляется вместо сырого картофеля.

## Артефакты и приложение

Канонический каталог подготовки — `data/product-directory/`. `catalog.json` внутри него является промежуточной сборкой продуктового этапа с замороженными прежними рецептами; рабочий совместный выпуск — **`data/catalog.json`**. Для восстановления актуального выпуска после продуктового этапа обязательно применяется каталог `data/recipe-adaptation/catalog.json`.

- `evidence.json` — 1055 категорий, принятые SKU, наблюдения, базы, диапазоны и пропуски.
- `aliases.json` — 5522 имени/алиаса только активных категорий; неподтверждённые архивные псевдонимы исключены.
- `pending-products.json`, `sku-audit.jsonl` — неполные категории и учёт каждого исходного SKU.
- `membership-first.json`, `membership-decisions.json`, `category-reviews.json`, `membership-changes.json` — оба прохода, решения и изменения.
- `classifications.json`, `excluded-classifications.json`, `classification-overrides.json`, `category-identifiers.json` — предложения и закреплённые ID.
- `verified-supplements.json`, `sources/`, `preview/sources/` — подтверждения маркировок/фасовок и страницы.
- `cleanup-verification.json`, `verification.json`, `replay-verification.json` — полная проверка и идентичность повторной сборки.
- `migration-report.json` — backup и результат применения продуктового этапа. Исторический справочник до очистки хранится отдельно.

SQLite: `product_directory` хранит происхождение, `product_skus` — только принятые связи полных категорий, `catalog_skus` — исходный MCP JSON, `product_aliases`/`product_fts` — рабочий поиск. `Catalog.product_sources` и `Catalog.source_skus` раскрывают доказательства и исходные карточки. `Catalog.products()` включает служебные записи для чтения старых рецептов. Обычный импорт сохраняет управляемый поиск. Shopper использует принятые price_observations для дополнения отсутствующей фасовки найденного SKU. С 20 октября Shopper дополняет top-10 MCP точными связями product_skus; свежий MCP при совпадении ID имеет приоритет. Источник и дата цены сохраняются. Семантическое соответствие по-прежнему оценивает модель; связь не подтверждает пригодность формы сырья для любого рецепта. Явные unit conversions и подтверждённые package_observations описаны в [UX-аудите](ux-audit.md). Текущий выпуск: 953 продукта, 948 активных, 4997 связей.

## Воспроизведение

Сохранённые решения позволяют собирать данные без сетевых/модельных вызовов. Для проверки сборки используйте отдельный каталог с копиями входных JSON; seed фиксирует прежние ID, единицы и рецепты:

```bash
uv run python -m app.preparation.directory data/preparation/enrichment.sqlite data/vkusvill/products.sqlite data/catalog-cleanup/runtime-seed.json data/product-directory
```

Проверены побайтовая идентичность `catalog.json`, `evidence.json`, `aliases.json`, `sku-audit.jsonl`, `pending-products.json`, `report.json`, числовая арифметика всех активных категорий, единицы, связи, FTS и сохранность исходных карточек. Их SHA256: `85181607d0a6a159b2f610bac280ad327b811d0ae79732ee8ce22fd4514cf105`.

`directory_apply` создаёт backup, сохраняет текущие рецепты буквально и заменяет продуктовые таблицы. `cleanup_verify` проверяет этот отдельный этап сразу после применения, до намеренного обновления рецептов. После совместного выпуска используется `adaptation_verify`: она разрешает задокументированное обновление чисел/архивацию неподдерживаемых вариантов и проверяет сохранность истории и четырёх прежних рецептов. [Последовательность выпуска и приёмка](catalog-cleanup.md).

Старый результат **927 категорий/5324 связи**, 123 теста первоначальной миграции и локальный отбор 13 категорий для 15 рецептов относятся к предыдущим этапам. Они не заменяют текущую полную очистку. [Исторический выпуск рецептов](recipe-rebuild.md).
