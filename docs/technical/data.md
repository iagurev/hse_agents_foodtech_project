## Каталоги и состояние

| Хранилище | Содержание |
|---|---|
| `data/recipes.sqlite` | Опубликованные рецепты, FTS, метаданные выпуска |
| `data/products.sqlite` | Нормализованные продукты, алиасы, принятые связи с SKU, фасовки и доказательства числовых оценок |
| `data/sources.sqlite` | Исходные MCP-карточки, рецепты и документы, происхождение и результаты подготовки |
| `../hse_agents_runtime/assistant.sqlite` | Аккаунты/сессии, анкеты, память, чаты, журнал, выполнения, версии планов/покупок и живые кэши |

Три каталога поставляются через Git LFS и открываются приложением только для чтения. После клонирования нужен `git lfs pull`: pointer-файл не является SQLite. Runtime создаётся отдельно; в Docker он находится в томе `k-stolu_runtime`. Все пути задаются в [Config](../../src/app/config.py).

В каталоге 693 рецепта и 953 продукта, из которых 948 активны. Неполные исходники сохраняются для дальнейшей подготовки и не становятся готовыми рецептами автоматически. Импорт и пополнение не запускаются во время диалога.

## Основные сущности

- **Продукт:** устойчивый `product_id`, общее название, единица `g/ml/pcs`, базовое количество, КБЖУ, средняя цена/диапазон и ограничения. Существенные виды сырья и состояния разделяются. Коэффициенты перевода единиц имеют источник и пометку оценки.
- **Рецепт:** `recipe_id`, название, базовая порция, ингредиенты с `product_id` и количеством, КБЖУ/цена порции, сложность, время, оборудование, ограничения, шаги, фото и первоисточник. КБЖУ округлены до целых, цены до копеек; количества сохраняют нужную точность. Шаги не повторяют общий расход ингредиентов, но сохраняют температуры, длительности и технологию.
- **SKU:** магазинный ID, цена, единица продажи, подтверждённая фасовка и происхождение наблюдения. Исходный MCP JSON остаётся в `sources.sqlite`; runtime-кэш не переписывает каталог. При совпадении ID данные MCP имеют приоритет над снимком.
- **План:** дни, приёмы пищи, рецепты и порции, ограничения, рассчитанные показатели и замечания.
- **Покупка:** продукты и назначения рецептов, выбранные SKU/количества, нерешённые позиции, стоимость и магазинные ссылки. Отдельной сущности «потребность» нет.

Точные типы находятся в [models.py](../../src/app/models.py), проекции UI — в [web/presentation.py](../../src/app/web/presentation.py). Схемы аргументов и результатов tools определены в [tools.py](../../src/app/assistant/tools.py).

## Версии и независимые данные

Каждая правка плана или покупки сохраняет новую версию со связью с предыдущей. Метаданные корня цепочки хранят общее название, скрытие и известное время создания. Скрытые объекты доступны по ID; старые версии не подменяются актуальными. Отметки «Куплено» переносятся только при неизменных SKU и количестве.

Полный журнал чата, его сводка и общая память пользователя хранятся отдельно. Сжатие меняет сводку и границу истории, но не удаляет журнал и не обновляет память. Квитанции операций обеспечивают повторную доставку без повторного сохранения результата.

Стоимость плана — оценка расхода ингредиентов. Покупка учитывает упаковки и весовые количества; суммы могут различаться. Неизвестная цена остаётся неизвестной. Полная структура не означает доказанной совместимости с любым свободнотекстовым ограничением.

## Проверка и обновление каталогов

```bash
uv run python -m app.catalog.check
```

Проверка читает согласованность выпуска, SQLite integrity/FK, межфайловые ссылки, FTS, числовые расчёты, происхождение рецептов и контрольные суммы исходных документов. SQLite не обеспечивает внешние ключи между отдельными файлами, поэтому межфайловая проверка обязательна.

Обновлять три БД нужно согласованно, с резервной копией и перезапуском приложения; горячая замена не поддерживается. Производный RAG-индекс привязан к хешам каталогов и пересобирается вне `data/`. Неподтверждённые КБЖУ, фасовки и коэффициенты не восстанавливаются догадками модели. Успешная техническая проверка не заменяет предметную проверку рецептур и маркировок.
