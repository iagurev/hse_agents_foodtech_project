# Эксплуатация и диагностика

Октябрь 2026 · Implemented

Команды запуска и проверок — в [README](../../README.md), параметры — в [.env.example](../../.env.example) и [Config](../../src/app/config.py). Приложение рассчитано на один процесс над пользовательской БД.

## Готовность и внешние подключения

- `/api/health` показывает готовность, доступность чата и состояние RAG. Первый запуск загружает модель поиска и строит индекс; ждать нужно `Application startup complete`.
- Нет OpenRouter-ключа — чат отключён, локальный поиск и просмотр доступны. Модели, их таймауты и reasoning настраиваются централизованно.
- [Публичный MCP ВкусВилла](https://mcp.vkusvill.ru/) подключён через официальный Python MCP SDK без авторизации. Используются готовые поиск, аналоги и создание ссылки. Предел операции — 60 секунд; независимые поиски выполняются с параллельностью до четырёх.
- Неизвестная фасовка/товар остаётся нерешённой позицией. Отказ создания ссылки сохраняет локальную покупку с ошибкой; прежняя ссылка не выдаётся за обновлённую.
- Фото ВкусВилла доставляются через `wsrv.nl`, Gastronom напрямую. Маршрут изображения ограничивает тип, размер 8 MiB и время 20 секунд; успешный ответ кэшируется браузером на сутки. При отказе UI показывает заглушку.
- После рестарта незавершённые ходы помечаются прерванными и не запускаются повторно. Перед обслуживанием сохраняйте runtime-БД; `docker compose down` сохраняет том, удаление тома — нет.

## Langfuse

Langfuse запускается отдельно по [официальной инструкции Docker Compose](https://langfuse.com/self-hosting/deployment/docker-compose). Создайте проект и его ключи, затем настройте приложение:

```dotenv
LANGFUSE_ENABLED=true
LANGFUSE_BASE_URL=http://127.0.0.1:3001
LANGFUSE_PUBLIC_KEY=pk-lf-...
LANGFUSE_SECRET_KEY=sk-lf-...
LANGFUSE_ENVIRONMENT=local
```

Для приложения в Docker и Langfuse на хосте задайте `LANGFUSE_DOCKER_URL=http://host.docker.internal:3001`. После изменения `.env` перезапустите приложение. По умолчанию трассировка выключена.

Один `chat.turn` — один ход, `session_id` — чат, `user_id` — владелец. Повторная доставка веб-хода не создаёт новую трассу. Пример вложенности:

```text
chat.turn
├── input_guard → generation
└── assistant
    ├── generation → выбор tool
    ├── generate_plan
    │   ├── plan.catalog
    │   ├── meal_plan.generate → generation
    │   └── plan.validate → при необходимости meal_plan.repair
    ├── create_cart
    │   ├── cart.aggregate / cart.search → MCP
    │   ├── product_selection.generate → generation
    │   └── cart.calculate → ссылки MCP
    └── generation → ответ
```

В **Tracing** фильтруйте `chat.turn` по Session ID. Timeline показывает длительности и параллельность; раскрывайте tool до конкретной generation и её Input/Output. Редакторы и compaction появляются только при соответствующей операции. `partial`, `needs_revision`, `blocked` отмечены WARNING; ошибки, отмена и прерывание — ERROR.

Стоимость записывается на generations, а не повторно на родителях; фактическое значение OpenRouter приоритетнее оценки тарифа. Reasoning уже входит в output. Длительности родительского и вложенного span нельзя складывать. У отменённого запроса usage может остаться неизвестным.

Экспорт работает в фоне: недоступный Langfuse не прерывает задачу, аварийная остановка может потерять неотправленные spans. В traces есть диалог, анкета, память и результаты tools, поэтому проект должен быть закрытым. Удаление чата не удаляет traces; retention настраивается отдельно. Пароли, cookies и API-ключи не собираются. Реализация — [tracing.py](../../src/app/tracing.py), основа — [интеграция Pydantic AI](https://langfuse.com/integrations/frameworks/pydantic-ai).

## Проверки и границы качества

Детерминированные тесты покрывают схемы, четыре проверки меню, расчёты покупок, изоляцию пользователей, версии, повторы, остановку и compaction. Frontend-проверки покрывают предварительную арифметику; навигация и формы дополнительно проверяются через браузер. Правильный JSON и проход тестов не доказывают смысловую точность произвольного меню или редакторской правки.

Ориентиры одной живой серии в октябре 2026: меню на три дня — 54 с, покупка — 45 с, изменение порции — 11 с. Покупка в этой серии была частичной; время зависит от провайдера, кэша, состава и коррекции. Это измерения отдельных запросов, не SLA.

Основные ограничения: неполная разметка состава/диет и фасовок, модельный выбор порций и товаров, оценочный локальный подсчёт токенов, возможная потеря смысловых деталей при сжатии, внешние фотографии. Полнота подбора и соответствие всем предпочтениям требуют проверки результатов. Реальная экранная клавиатура телефона и screen reader не входят в проведённую браузерную приёмку.
