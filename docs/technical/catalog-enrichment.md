## Правила

Исходные 2508 рецептов и 7492 товарных карточек учитываются полностью. Для каждой исходной записи сохраняются источник, результат обработки и причины незавершённой подготовки. Подготовленная запись рецепта проходит существующий PreparedCatalog; недостаток фактов не заполняется нулями или выдуманными значениями. Преобразование КБЖУ на 100 г в порцию требует установленной массы или независимого расчёта ингредиентов.

Карточки ВкусВилла сохраняются целиком в исходном MCP-формате. Внутренний Product — отдельная проекция. Неправдоподобный weight=1 кг у штучных товаров не используется для определения фасовки. Исходное поле сохраняется.

Дедупликация использует устойчивые ID, канонические URL и точный содержательный отпечаток. Совпадение названия само по себе не объединяет рецепты. Нормализация продуктов сохраняет жирность, обработку, часть продукта и другие существенные уточнения; общий архивный тип не является свидетельством взаимозаменяемости. Единицы существующих продуктов и их ID сохраняются.

Подготовка выполняется отдельно от диалога, повторный запуск воспроизводим. Перед применением создаётся SQLite backup. Обновление рабочего каталога атомарно; пользовательские объекты и история сохраняются.

## Политика подтверждённых данных

Пользователь выбрал: «Только подтверждённые данные; неполные рецепты сохранять для доработки». Расчёт из известных величин допустим; справочные массы яиц, ложек, щепоток, плотности жидкостей и условное среднее диапазона не подставляются. Предыдущие четыре проверенные записи сохраняются; новая подготовка не распространяет их редакторские ставки на новые рецепты.

Общий продукт сохраняет прежнюю единицу, если он уже существует. Для нового продукта выбирается наиболее частая наблюдаемая поддерживаемая единица полного нормализованного названия. Иные единицы в рецептах остаются нерешёнными; смена единицы не выполняется. Существенные уточнения сохраняются в имени. Лексические синонимы объединяются ограниченным явным словарём; архивные broad mappings не используются как основание объединения.

Пищевая ценность и цена нового общего продукта могут быть дополнены только единственной карточкой с полностью совпавшим именем и совместимой базовой единицей. Источник SKU и дата указываются в restrictions и отдельном журнале; разные карточки не усредняются. Сомнительные числовые маркировки отмечаются для проверки; исходные значения не исправляются.

## Файлы и повторение

- `data/vkusvill/products.sqlite`, `products.jsonl`: все исходные MCP-карточки; JSONL содержит только исходные поля, метаданные наблюдений находятся отдельно в SQLite.
- `data/sources/vkusvill-recipes/`: сжатый HTML, JSON-LD и журнал запросов первоисточника.
- `data/preparation/enrichment.sqlite`: исходные реляционные таблицы плюс preparation_recipes, preparation_products, preparation_ingredients, preparation_sku_references.
- `data/preparation/recipes-review.jsonl`: все 2508 рецептов с извлечёнными facts, evidence, статусом и конкретными blockers.
- `data/preparation/catalog.json`: только данные действующего PreparedCatalog; переносится в `data/catalog.json` и рабочую SQLite.
- `data/preparation/report.json`: полный учёт, заполненность полей и причины доработки.

```bash
uv run python -m app.preparation preserve-mcp SOURCE_PRODUCTS_SQLITE data/vkusvill
uv run python -m app.preparation fetch-pages SOURCE_FOOD_SQLITE data/sources/vkusvill-recipes
uv run python -m app.preparation prepare SOURCE_FOOD_SQLITE data/sources/vkusvill-recipes data/preparation/seed-catalog.json data/preparation data/vkusvill/products.sqlite
uv run python -m app.preparation apply data/preparation/catalog.json data/catalog.json data/assistant.sqlite data/backups
```

Неполные рецепты доступны в базе подготовки, но не участвуют в поиске рабочего каталога или генерации меню. Это сохраняет обязательность полей действующего контракта. Товарный снимок является отдельным MCP-совместимым источником; обычный runtime по-прежнему использует настроенную живую интеграцию, без скрытой подмены устаревшими данными.
