# Финальные базы данных и архив подготовки

- Status: Implemented
- Дата: 2026-10-19.
- Авторизация: пользователь поручил оставить в репозитории только три финальные базы рецептов, продуктов и исходников, а промежуточные данные и скрипты перенести рядом с репозиторием в `/Users/ilya/HSE/Course2/Agents`.

`data/recipes.sqlite` содержит только опубликованные рецепты и их FTS-индекс. `data/products.sqlite` содержит готовые продукты, совместимые прежние продукты, принятые связи SKU, алиасы, числовые доказательства и продуктовый FTS. `data/sources.sqlite` содержит исходные MCP-карточки без изменения, исходные рецепты, окончательный реестр их обработки и исходные документы/доказательства. Доступ приложения к трём файлам — только чтение; JSON-копия каталога и импорт при запуске не нужны.

Личные данные, журнал диалогов, планы, корзины и живой SKU-кэш хранятся в отдельной создаваемой приложением БД вне репозитория, по умолчанию `../hse_agents_runtime/assistant.sqlite`; токенизатор — в `../hse_agents_runtime/tokenizer`. Настройки путей централизованы в Config. Существующие пользовательские записи сохраняются при переносе; каталог из runtime не дублируется.

Скрипты разовой подготовки, их тесты, исходные tar.gz, HTML/JSON-кэши, прежние выпуски, backup и незавершённые исправления сохраняются в `../hse_agents_data_archive/2026-10-19/`. Архив включает снимок кода и окружения до реорганизации, перечень перенесённых путей и контрольные суммы. В рабочем пакете остаются код чтения каталога и проверка трёх финальных БД.

SQLite не поддерживает внешние ключи между отдельными файлами: целостность recipe→product и product_sku→source проверяется проверяющей командой, внутренние ключи остаются в своих БД. ID, payload, единицы, числовые значения, FTS, алиасы и native JSON при переносе не меняются. Устаревшие локальные пути источников в evidence являются ключами документов `sources.sqlite`, а не требованием восстановить старую папку data.

Приёмка: ровно три файла SQLite в data; все 693 рецепта, 833 продукта (826 активных), 7492 native SKU, 4701 принятая связь, 5522 имени/алиаса и все 2508 источников сохранены; приложение читает эти файлы, поиск/детали/происхождение работают; личные данные не попали в финальные наборы; нет зависимостей runtime от перенесённых скриптов/артефактов; тесты, lint и сборка проходят.


## Схемы и проверка

| Файл | Основные таблицы | Проверенный объём |
| --- | --- | --- |
| recipes.sqlite | recipes, recipe_fts, metadata | 693 рецепта, около 3,8 МиБ |
| products.sqlite | products, product_directory, product_skus, product_aliases, product_fts, metadata | 833 продукта, 826 активных, 4701 связь, 5522 алиаса, около 5,2 МиБ |
| sources.sqlite | catalog_skus, recipe_sources, recipe_preparation, recipe_origins, product_audit, sku_audit, documents, document_aliases, reports, metadata | 7492 SKU, 2508 источников/решений, 1055 категорий аудита, 6134 документа, около 225 МиБ |

`recipe_sources.payload` сохраняет исходную запись выгрузки; `recipe_preparation.payload` — окончательный реестр с оригиналом, редакторской рецептурой, проверками и причинами незавершённости. Статусы: 676 ready, 13 preserved_ready, 1819 needs_revision. Recipe_origins связывает все 693 рабочие карточки с источником. Product_audit содержит и неполные категории, не попавшие в рабочий справочник. Reports хранит компактные финальные доказательства прежних этапов по прежнему относительному пути как ключу. Documents содержит сжатые исходные байты с SHA256 распакованного содержимого; Catalog.source_document разрешает также сохранённые алиасы путей.

```bash
uv run python -m app.catalog_check
uv run meal-app
```

Проверка открывает все файлы только для чтения: общий ID выпуска/версия схемы, SQLite integrity/FK, межфайловые ссылки, полнота FTS, публичные payload относительно реестра, арифметика новых адаптаций, native MCP ID/SHA и все 6134 документа. В data не создаются отчёты или вспомогательные БД. Настройки: RECIPES_DATABASE_PATH, PRODUCTS_DATABASE_PATH, SOURCES_DATABASE_PATH, DATABASE_PATH и TOKENIZER_CACHE_PATH.

При переносе все исходные payload и строки FTS/алиасов/связей побайтово сохранены. SHA native MCP: `85181607d0a6a159b2f610bac280ad327b811d0ae79732ee8ce22fd4514cf105`. Проверено 4954 вхождения ингредиентов всего каталога, в том числе прежние 4935 у новых адаптаций. Для четырёх независимых старых рецептов исходные числа сохранены; их старые редакторские цены не объявляются новыми агрегатами VV.

Архив: `../hse_agents_data_archive/2026-10-19/` — 14687 перенесённых файлов, 2471073936 байт, оба исходных tar.gz, все этапы, backups и 27 разовых модулей подготовки. `archive-manifest.json` содержит размеры/SHA; полный согласованный снимок src/tests/окружения сохранён отдельно от рабочего кода. Секретный .env не копировался. Токенизатор, который нужен приложению, перенесён в runtime-кэш. Все 12 таблиц состояния перенесены без изменения, каталожные таблицы удалены из runtime-копии; исходная объединённая БД сохранена в архиве.

Проверены поиск/детали омлета, курицы, творога и чечевицы, чтение всех 37 native SKU творога и документа яблока. После запуска HTTP-приложения финальные файлы не изменяются; health/frontend возвращают 200, неавторизованный API — 401. Модельных вызовов для переноса и проверки не требуется.

После отдельного поручения пользователя компактная проекция Planner занимает 125945 токенов каталога вместо прежних 394229. В recipes.sqlite после backup округлены КБЖУ до целых, цены до копеек; metadata.recipe_number_format=nutrition-integer-cost-cent-half-up-v1 отмечает формат публикации того же базового выпуска. Продукты, исходники, проверки источников и runtime побайтово сохранены. Незавершённое подключение принятых SKU/фасовок к Shopper остаётся отдельной задачей.

Рабочий набор проверен 133 тестами, Ruff и сборками sdist/wheel. Подготовительные скрипты и их прежние тесты вынесены в архив; снижение общего числа тестов относительно исторических 223 отражает разделение рабочего пакета и разовой подготовки. Новые проверки покрывают read-only, смешение выпусков, отсутствие БД, межфайловые ссылки, происхождение документов и совпадение опубликованной рецептуры с сохранённой проверкой.
