# Подключение ВкусВилла

- Status: Implemented
- Обновлено: 2026-10-19.
- Основание: поручение подключить публичный MCP без авторизации и переиспользовать поиск, аналоги и готовую ссылку корзины.

Приложение напрямую вызывает **https://mcp.vkusvill.ru/mcp** через официальный Python MCP SDK `mcp==1.30.0` (Streamable HTTP). Ключ, OAuth, локальный товарный сервер и отдельный LLM-агент магазина не нужны. Настройка — `VKUSVILL_MCP_URL`; прежние `VKUSVILL_BASE_URL` и `VKUSVILL_ANALOGS_URL` больше не используются. Поиск наличия, персональные скидки, история заказов и оформление заказа не подключаются.

## Переиспользуемые операции

| Операция приложения | Готовый инструмент MCP | Передаваемые аргументы |
| --- | --- | --- |
| `search_products`, внутренний поиск ингредиентов | `vkusvill_products_search` | `q` без переписывания, `page=1`, `limit=10`, `sort=popularity`, `vvonly=1`, `mode=custom`, поля `id,name,price,unit,url,properties` |
| `get_product_analogs` | `vkusvill_product_analogs` | `id` найденного товара; приложение оставляет первые 10 результатов |
| Создание и обновление ссылки покупки | `vkusvill_cart_link_create` | `products: [{id, q}]`, из выбранных SKU и количеств |

Публичные Pydantic-контракты агента не меняются. Внутренний `sku_id` — строковое представление native `id`. Схемы MCP не добавляются второй копией в контекст модели: тонкий адаптер переводит существующие предметные вызовы в три готовые операции сервера.

Фактический `tools/list` 19.10.2026 у обоих адресов (`mcp.vkusvill.ru/mcp` и `mcp001.vkusvill.ru/mcp`) требует **id**, а не xml_id. На публичной странице документации ещё приведён xml_id. Использована проверенная схема endpoint, подтверждённая реальной ссылкой. Схема разрешает до 30 SKU, q от 0.01 до 40, хотя её текстовое description говорит 1..20. Приложение сохраняет существующий целочисленный контракт количеств: 1–40 единиц и до 30 разных ID. Лишние позиции не отбрасываются и не разбиваются незаметно на несколько ссылок; превышение даёт link_error сохранённой корзины.

## Данные и ошибки

- Поиск возвращает `data.items`, аналоги — `data.products`, создание ссылки — `data.link` внутри успешного `ok=true`. Поддержаны JSON-текст MCP и structuredContent. isError, ok=false, ошибки транспорта и неверный формат отличаются от корректного пустого списка.
- `price.current` с currency=RUB — цена в рублях. Деления по величине числа или подстановки нуля при отсутствии цены нет. Состав читается из properties с name=«Состав». Весь маркетинговый текст, фотографии и остальные неиспользуемые поля не передаются модели выбора SKU.
- Для единицы продажи кг/л один q означает 1000 г/мл. У штучного товара используется явная однозначная фасовка в названии, с указанием источника. `weight` не принимается за достоверную фасовку: живой ответ для творога 400 г (id=185) содержит weight=1 кг. Без подтверждённой фасовки ингредиент остаётся unresolved; г↔мл и масса одной штуки не угадываются.
- Версии корзин, исходные MCP-снимки в sources.sqlite и справочники не переписываются. Ключ кэша поисковых кандидатов получил префикс mcp-v1: старые проекции HTTP-посредника не подмешиваются в новый поиск. Найденные native ID сохраняются в существующем sku_records для редактора и прямого создания корзины.
- Один вызов владеет короткой MCP-сессией, используя общий HTTP-пул товарного подключения. initialize и tools/list выполняются до tools/call. Схемы проверяет SDK; они не копируются вручную в промпты. Независимые поиски идут параллельно с существующим пределом Shopper (4).
- `INTEGRATION_TIMEOUT_SECONDS=60` ограничивает всю операцию, включая согласование протокола; HTTP timeout настроен отдельно от клиента модели. Повторные tools/call автоматически не запускаются, отмена распространяется наружу. После ошибки ссылки найденная часть сохраняется, прежняя ссылка не подставляется.
- Логи содержат имя операции, длительность, тип ошибки и HTTP-код; запрос пользователя, состав корзины и payload в них не пишутся.
