> Хранение обновлено: текущие три БД и способ запуска описаны в [data-storage](data-storage.md). JSON/JSONL, отчёты и команды подготовки ниже относятся к архиву `../hse_agents_data_archive/2026-10-19/`; выполнять их следует только в согласованном архивном снимке кода. Рабочее приложение не импортирует эти JSON и не содержит разовых скриптов.

- Status: Implemented (доступный офлайн-выпуск; неполные записи сохранены)
- Дата: 2026-10-19.
- Авторизация: пользователь поручил полностью очистить справочник, пересчитать цены/КБЖУ по подходящим SKU и строить адаптации от существующих продуктов. Отдельно разрешил новые граммовки в явно помеченных адаптациях; прежний запрет редакторских количеств для этой задачи отменён. Числовые данные маркировки и цен по-прежнему не выдумываются.

Все 7492 исходные MCP-карточки учитываются и остаются неизменными. Проверяются все текущие категории, все включённые SKU и прежние исключения. Общие категории остаются уровнем кулинарного продукта: фасовки, бренды и обычная жирность объединяются, существенные виды сырья, наполнители, готовые смеси и состояния различаются. Неподходящий SKU перемещается в существующий подходящий тип или остаётся явно неразрешённым, а не загрязняет числовой агрегат. Неполный продукт не получает вымышленных нулей или конверсий.

Проверка включает отдельные решения по каждому SKU на основе названия, состава и отдела; затем повторную проверку состава каждой полученной категории, предметные защиты и проверку подозрительных числовых наблюдений. Агрегаты строятся только по принятым SKU с совместимой физической базой. Каждое исключение/перемещение, наблюдение, число и источник сохраняются. Полнота проверки означает учёт каждой записи, а не гарантию безошибочности модельного суждения; неразрешённые случаи остаются в отчёте.

Категории и рабочие ID по возможности сохраняются. История, объекты и исходные рецепты сохраняются; единица существующего используемого ID не меняет смысл количества. Перед применением создаётся backup. Старые показатели не остаются числовым источником новых рецептов через служебные записи.

После очистки все 2508 рецептов повторно рассматриваются как источники для собственных адаптаций от доступных продуктов. Допускаются обобщения внутри кулинарно совместимой категории, удаление второстепенных компонентов и новая явно редакторская граммовка. Такая граммовка — состав новой адаптации, а не утверждение, что исходные две штуки/ложки весили столько граммов. Необходимые жиры, связующие и основа не удаляются ради прохождения проверок. Инструкции согласуются с новым составом; противоречия или непригодность основной технологии блокируют выпуск. Точное соответствие оригиналу не требуется.

Новые варианты имеют отдельный устойчивый ID, понятный состав, базу показателей, пометку авторской адаптации и ссылку на источник вдохновения. В facts сохраняются весь оригинал, сопоставления, исключения, новая рецептура и её редакторское происхождение. Цены/КБЖУ считает код по очищенным продуктам; модель не генерирует числовую маркировку. Время исходника сохраняет происхождение, а изменение времени при новой технологии без подтверждения не маскируется под исходный факт. Повторная сборка выполняется из сохранённых решений без новых модельных запросов.

## Проверенный продуктовый этап

В рабочую SQLite применены 826 полных категорий, 4701 связь с принятыми SKU и 5522 имени/алиаса. Изменились 1300 сопоставлений; 744 товара перенесены между существующими категориями. Неполные 229 категорий и 555 неразрешённых SKU сохраняются отдельно. У 160 категорий нет полного КБЖУ, у 73 — совместимой базы цены; четыре входят в обе группы.

Все 7492 карточки MCP неизменны: SHA256 `85181607d0a6a159b2f610bac280ad327b811d0ae79732ee8ce22fd4514cf105`. Проверены каждый числовой агрегат, базы единиц, полный набор ID, связь каждого наблюдения с принятым SKU, FTS и сохранность таблиц. Продуктовый этап сохранил 19 рецептов буквально; следующий этап намеренно обновляет числовую базу 13 поддерживаемых VV-рецептов и архивирует два неподдерживаемых варианта с фисташками. Четыре прежних рецепта другого источника и их семь совместимых продуктов сохраняются.

Повторный build из замороженного `data/catalog-cleanup/runtime-seed.json` побайтово идентичен для каталога, evidence, алиасов, SKU-аудита, неполных продуктов и отчёта. [Детали справочника](product-directory.md).

## Авторская подготовка и проверка

Исходный реестр: `data/recipe-rebuild/recipes-review.jsonl`, все 2508 ID. Отдельно сохраняются оригинальные инструкции и данные страницы, редакторский состав, его происхождение и замечания проверки. Выбор продукта передаётся буквальным именем из native enum; индекс присваивает код. Один исходный компонент допускает несколько новых продуктов при разложении смеси, но не может одновременно считаться включённым и исключённым.

Числа состава относятся ко всей редакторской партии. В Recipe.amount, nutrition и cost хранится одна новая базовая порция; шаги описывают всю указанную партию и это явно отмечено. Яйца задаются съедобной массой без скорлупы. Все КБЖУ/цены считаются кодом из очищенных категорий. Никакие исходные «2 штуки» не объявляются измеренными 100 г.

Проверяющий получает исходник, новую рецептуру, инструкции, маркировку и названия реальных SKU. В частности, отличает спред «Масло вег» от жидкого масла, сливки разной жирности от отдельного продукта для взбивания, готовый жареный лук от сырого. Отделение сыворотки, использование только белков при маркировке целого яйца, фильтрация кофейной гущи и слив значительного сиропа не позволяют посчитать весь исходный продукт съеденным. Явное ожидание дольше total источника блокирует выпуск; новые времена не подставляются.

Числовые температуры/длительности сверяются с источником с нормализацией записи (`180С` = `180 °C`, `1 час 20 минут` = `80 минут`). Существенные подтверждённые этапы нельзя удалять ради прохождения проверки. Отклонённый вариант допускает адресное исправление и повторные шаги/проверку; успешные варианты не меняются. Исправление не заменяет повторную приёмку. Повторный build читает сохранённые решения без запросов к модели.

## Завершение доступного набора без модели

Пользователь выбрал офлайн-завершение после исчерпания лимита OpenRouter. Сохранённые авторские планы, инструкции и отдельные кулинарные проверки используются повторно; новые вызовы модели не выполняются. Финальная проверка точного состава допускает явно обозначенный детерминированный проход с выборочной предметной проверкой агентом. Он не объявляется вторым модельным или полным ручным аудитом. Неоднозначные ложки/штуки, физические единицы, отделяемые части яйца, неиспользованные продукты и явный слив пищевой части блокируют выпуск. У решений сохраняются метод, версия правил, конкретные замечания и хеш точной проверенной рецептуры. Доступные предложения адресных исправлений без повторных инструкций и кулинарной проверки остаются черновиками.

## Опубликованный результат

В `data/assistant.sqlite` и `data/catalog.json` находятся **693 рецепта**: **676 новых авторских адаптаций**, 13 поддерживаемых прежних VV-рецептов с обновлённой числовой базой и четыре прежних рецепта другого источника без изменения. Два прежних неподдерживаемых варианта с фисташками архивированы вместе с исходным payload и ссылкой на backup; служебный неиспользуемый продукт удалён. Для четырёх старых рецептов остаются семь совместимых продуктов, всего в SQLite 833 продукта.

Все **2508** исходников учтены: 676 ready + 13 preserved_ready + **1819 needs_revision**. Из 2495 новых заданий 2016 получили осуществимый авторский состав, 479 — мотивированный отказ. Для всех 2016 сохранены инструкции и отдельные кулинарные проверки. После предметных и числовых защит оставался 1251 кандидат; финальный консервативный офлайн-проход оставил 676. У 575 дополнительно отложенных кандидатов сохранены точный состав, инструкции и причины отказа. Некоторые отклонения консервативны и требуют индивидуального просмотра, а не означают принципиальную невозможность блюда.

Сохранены 408 предложений адресного исправления (`repair-partial-proposals.json`); они **не применены** к планам и не опубликованы без новых шагов и проверки. Массовое исправление остановлено из-за лимита ключа, затем пользователь выбрал завершение доступного набора офлайн. Лимит не обходился, новые вызовы модели не делались.

Новые адаптации используют **345 из 826** полных продуктов. Роли пересекаются: breakfast 135, lunch 335, dinner 300, snack 279, dessert 177. Это количество размеченных карточек, а не подтверждение разнообразия недельного меню или покрытия всех диет. КБЖУ и стоимость каждой базовой порции рассчитаны по очищенным категориям; источник маркировок и цен не менялся. Полного ручного предметного аудита всех рецептов не было.

Основные артефакты `data/recipe-adaptation/`:

- `catalog.json`, `recipes-review.jsonl`, `report.json` — совместный каталог и полный реестр исходников, решений, пропусков и новых количеств.
- `plans.json`, `steps.json`, `reviews.json`, `product-vocabulary.json`, `product-context.json` — сохранённая авторская работа и кулинарные проверки по фактическим SKU.
- `composition-reviews.json`, `composition-review-report.json`, `offline-spot-checks.json` — точные решения финального офлайн-прохода и 36 выборочных чтений состава/шагов, с методами и хешами. Случайные выборки воспроизводимы; замечания выборочного чтения расширены в общие защиты.
- `verification.json`, `preview-verification.json`, `replay-verification.json`, `runtime-smoke.json` — рабочая проверка, пробный выпуск на копии, повторная сборка и импорт, поиск и детали.
- `retired-recipes.json`, `migration-report.json`, `release-manifest.json` — архив неподдерживаемых вариантов, backup и отпечатки источников выпуска.
- `repair-partial-proposals.json` — не принятые к выпуску предложения исправления.
- `planner-context.json` — измерение ограничений текущего генератора меню.

Backup перед окончательным импортом: `data/backups/assistant-before-enrichment-20261019T045951317225Z.sqlite`. Более ранний backup перед архивированием двух рецептов закреплён в `retired-recipes.json`. Проверены сохранность пользовательских таблиц, всех 7492 MCP-карточек, четырёх прежних рецептов, 4701 связи SKU и FTS. Независимо пересчитаны все 4935 строк ингредиентов и показатели 676 адаптаций. Повторный импорт логически идентичен по 13 таблицам; повторная сборка побайтово идентична для каталога, реестра, отчёта и решений финального прохода.

### Ограничение рабочего агента

Текущий `Planner` передаёт полный каталог. Один JSON карточек 693 рецептов занимает **394229 токенов** закреплённого токенизатора GLM при настроенном пределе входа **232000**, ещё без запроса, контекста и схем. Сжатие истории не сокращает этот каталог. Нужна отдельная адаптация стратегии выбора рецептов; живая генерация меню по этому набору не проверялась и готовность полноценного пилота не заявляется. Поиск и чтение рецептов проверены офлайн. Shopper также пока не использует принятые `product_skus` и доказательства фасовок, внешняя ссылка корзины ранее возвращала 502.

### Повторная офлайн-сборка и выпуск

Перед повторным build сохраните копию артефактов или используйте отдельный destination с копиями `plans.json`, `steps.json`, `reviews.json`, `product-vocabulary.json`, `product-context.json`, `offline-spot-checks.json`. Build заново создаёт кандидатов, поэтому после него **обязательны** офлайн-проход и finalize. Без актуальных принятых composition-проверок release отклоняет новые адаптации.

```bash
uv run python -m app.preparation.recipe_adaptation build
uv run python -m app.preparation.offline_composition
uv run python -m app.preparation.composition_review finalize
uv run python -m app.preparation.adaptation_release data/recipe-adaptation data/recipe-adaptation-seed.report.json data/assistant.sqlite data/catalog.json data/backups
uv run python -m app.preparation.adaptation_verify data/recipe-adaptation data/product-directory data/assistant.sqlite PATH_FROM_NEW_MIGRATION_REPORT
```

Финализированный `data/recipe-adaptation/catalog.json` уже находится в рабочем экспорте и SQLite. Проверка повторной сборки выполнялась в `data/recipe-adaptation-replay/`; никаких сетевых вызовов для этих команд не требуется. Исторические результаты 19/15 и 927 категорий сохранены в документах прежних этапов и не описывают текущую базу.
