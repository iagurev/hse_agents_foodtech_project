# Устройство приложения

Октябрь 2026 · Implemented

React/Vite и FastAPI работают как небольшое мобильное веб-приложение. Один Python-процесс обслуживает HTTP, фоновые ходы агента и локальный поиск; SQLite хранит состояние. Запуск, модели и команды проверки — в [README](../../README.md).

## Сообщение и инструменты

Путь запроса: HTTP → input guard → `Session` → цикл Pydantic AI → tools → предметные операции → сохранение и SSE. Самостоятельных субагентов и отдельного оркестратора нет. Guard проверяет текущее сообщение, анкету и последние два разрешённых обмена; заблокированное сообщение видно в UI, но не попадает в контекст агента и compaction.

Описания, Pydantic-входы/выходы и обработчики всех 12 предметных инструментов и `update_memory` находятся рядом в [tools.py](../../src/app/assistant/tools.py). Это источник полных контрактов; общий системный промпт не повторяет схемы.

- `list_plans()` и `list_carts()` не принимают аргументов; скрытые цепочки не возвращаются.
- При создании и поиске `limits` передаётся явно; `null` означает отсутствие ограничения. Backend не подставляет анкету. Бюджет передаётся без прибавки, код допускает превышение до 5%.
- `edit_plan(plan_id, request)` и `edit_cart(cart_id, request)` получают самодостаточное поручение. Редактор возвращает полную версию без общего каталога и истории; условия текущего объекта сохраняются до явного изменения пользователем.
- `update_memory(text)` заменяет короткий общий текст. Runtime проверяет владельца и версию; конфликт возвращает актуальный текст для объединения. Память и сводка чата — разные сущности.

## Меню, поиск и покупки

**Меню.** Генератор получает весь каталог компактных карточек с временными короткими ID. Код восстанавливает постоянные ID, пересчитывает показатели и выполняет четыре проверки: существование рецепта, числовой формат, сложность, бюджет. На операцию разрешены генерация и одна коррекция, включая ошибки формата. Предметно некорректный результат остаётся адресуемым `needs_revision`; неразбираемый ответ — техническая ошибка. Отдельного LLM-верификатора нет.

**Поиск.** Лемматизированный FTS5/BM25 и локальный ONNX encoder объединяются через RRF, возвращая до 10 карточек. Явные ограничения состава, техники, времени, сложности, роли, типа питания и цены порции применяются до отбора. Парсера условий из query нет. При отказе dense используется лексический поиск с теми же фильтрами. Генерация меню не зависит от RAG. Индекс связан с хешами каталогов и строится до готовности приложения.

**Покупки.** Источник — план, рецепты с порциями либо готовые SKU с количеством. Для рецептов код агрегирует ингредиенты, получает MCP-кандидатов и точные связи каталога; модель пакетно выбирает товары. `request` буквально уточняет поиск, отдельно моделью не разбирается. Подтверждённые фасовки и коэффициенты позволяют рассчитать упаковки и стоимость; неизвестные данные не заменяются нулём. Готовые SKU идут к созданию ссылки без нового выбора. Правка сохраняет незатронутые SKU. Одна покупка может содержать несколько магазинных ссылок, до 30 разных SKU в каждой.

## История и пределы

Один активный ход на чат; разные чаты имеют общую анкету/память, но отдельную историю. SDK сохраняет reasoning внутри текущего цикла tools, не переносит его в следующий завершённый ход.

| Параметр | Значение |
|---|---|
| Окно / максимальный вход | 256 000 / 232 000 токенов |
| Резерв ответа / запас подсчёта | 16 000 / 8 000 |
| Порог сжатия / максимум сводки | 200 000 / 8 000 |
| Свежие завершённые ходы | 6 → 3 → 1 → 0 |
| Бюджет задачи / сжатия | 600 с и 12 запросов / отдельно 180 с и 2 запроса |

Размер проверяется перед каждым запросом чатового агента, в том числе после tools. Текущий ход не обрезается; сводка атомарно заменяет предыдущую только после успешного сжатия. Полный журнал остаётся в БД. Для Luna используется оценка `tiktoken/o200k_base` по SDK-сериализации с запасом; GLM имеет отдельный счётчик. Локальная оценка не гарантирует точного совпадения с usage провайдера.

## HTTP и версии

Серверная сессия хранится в HttpOnly cookie на 30 дней; изменяющие запросы проверяют происхождение, объекты — владельца. Полные HTTP-схемы доступны в `/docs` запущенного приложения.

Повтор с тем же ID хода возвращает существующее выполнение. SSE восстанавливает состояние после reconnect; закрытие страницы не останавливает работу. Stop сохраняет завершённые операции, рестарт помечает незавершённый ход `interrupted` без автоповтора. Удаление чата не удаляет планы, покупки и память.

Ручные правки используют исходную версию и ключ операции; устаревшая версия отклоняется. Показатели пересчитывает backend без LLM. Имя и скрытие относятся ко всей цепочке; старые карточки открывают свои версии. SSE и загрузка переписки используют одну проекцию, исключающую reasoning и внутренние инструкции.
