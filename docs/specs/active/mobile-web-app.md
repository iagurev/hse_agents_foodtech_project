## Пользовательский аудит, 20 октября 2026

Реализовано по поручению пользователя: исправление первого сообщения нового чата; компактная композиция подборки и группировка блюд одного приёма пищи; управление названием/скрытием во вторичном меню, сохранение порций при открытии рецепта из плана. Новые доменные tools и проверки плана не вводятся.

Уточнения пользователя: если агент вызвал `get_recipes`, карточки этого ответа показывают открытые им рецепты; иначе остаются найденные кандидаты. SSE и переписка после reload используют одно правило. Поля количества ингредиентов — единый источник: из шагов каталога удаляются дубли этих количеств, но сохраняются температуры, время, размеры и распределение ингредиента между этапами. Изменения данных выполняются отдельным аудитом, а не при открытии экрана.

Согласовано: справочные коэффициенты перевода единиц хранятся у нормализованного продукта с источником и пояснением оценки. Без коэффициента несовместимые единицы не пересчитываются. Кандидаты MCP дополняются точными связями product_id → SKU из подготовленного каталога; дата и происхождение цены сохраняются, живой ответ имеет приоритет для совпадающего SKU. Подбор получает только используемые рецепты, чтобы отличать, например, филе от грудки на кости. Проверка: яйца g/pcs, масло g/ml, отсутствие неизвестного коэффициента, доступность разрыхлителя вне первых 10 MCP, приоритет живой цены и совпадение расчёта до/после выбора.

Дополнительное решение пользователя: покупка остаётся одним объектом с единым составом и итогом. Более 30 различных SKU разделяются на несколько магазинных ссылок по лимиту MCP; состав не урезается. У каждой части сохраняются SKU, ссылка или ошибка. Отказ одной части не скрывает успешные ссылки. Старые покупки с одной ссылкой остаются доступны; редактирование обновляет все части, повтор доставки не создаёт их заново.

Приёмка WEB-18…21: реализовано; 244 Python/5 frontend, сборки и CUA 360/390/430, семь живых ходов с бюджетом $0.0869. Детали и предметные ограничения — в [аудите](../../technical/ux-audit.md#анкета-понятные-поручения-и-дневные-показатели).

## Наблюдаемость и ясность интерфейса, 20 октября 2026

Status: Implemented. Основание — поручение пользователя настроить Langfuse, проверить вес и упростить подписи анкеты.

- WEB-22: второй шаг без общей подписи о необязательности и повторяющихся пометок. В пользовательских пояснениях используются «товары», а не SKU. Вес 70 сохраняется при регистрации, правке и повторном открытии; диапазоны не меняются.
- OBS-01: один trace на новый ход; chat_id объединяет сессию, user_id — внутренний ID, без логина/пароля/cookie. Повтор доставки не запускает новый trace исполнения.
- OBS-02: guard, разговорный агент, tools, внутренние модели, compaction и существенные этапы расчётов/товарной интеграции связаны родительскими spans. Нативная инструментация SDK сохраняет вход/выход и usage; фактическая цена OpenRouter учитывается только на generation, общие суммы — в metadata корня.
- OBS-03: ошибки/отмена и частичный результат различимы; одновременные чаты не смешиваются. Экспорт асинхронный, отказ Langfuse не прерывает пользовательскую задачу. Клиент и exporter завершаются при остановке приложения.
- OBS-04: подключение опционально через Config. Для локального запуска используется уже доступный Langfuse; секреты вне Git, сырой журнал промптов остаётся только в закрытом локальном проекте наблюдаемости.

Приёмка: регрессии API/трассировки, CUA анкеты и дерева реального trace, проверки frontend/Python и сборки; README соответствует GROUP_PROJECT.md курса, содержит участников, роли моделей, Docker-запуск и четыре актуальных снимка.

Приёмка WEB-22/OBS-01…04: 248 Python/5 frontend, Ruff/TS/сборки, Docker, CUA анкеты и Langfuse, шесть живых сценариев ($0,04171). Compaction проверен детерминированно, доступность внешних товаров остаётся отдельным ограничением. [Отчёт](../../technical/verification.md#langfuse-анкета-и-readme--2026-10-20).
