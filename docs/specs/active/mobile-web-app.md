| WEB-18 | Видимый текст карточек содержит названия; ссылки на точные версии передаются отдельно и проверяются по владельцу | API, UI |
| WEB-19 | Регистрация: обязательный основной шаг, затем пропускаемый шаг активности, бюджета, сложности и ограничений; переход назад сохраняет введённое | API, UI |
| WEB-20 | Меню учитывает физические данные и цель; пропуск активности не блокирует подбор. Указания диалога приоритетны | Модельные сценарии |
| WEB-21 | КБЖУ меню показываются в среднем за день; показатели блюда и выбранного дня, общая стоимость сохраняются | Расчёты, UI |
| WEB-22 | Дополнительный шаг без повторных пометок необязательности; пользовательские подписи говорят о товарах. Вес сохраняется при регистрации и правке | API, UI |

В чате показываются открытые агентом рецепты как итоговая подборка, иначе — найденные кандидаты. Порции сохраняются при переходе из плана в рецепт. Количества ингредиентов берутся из единого списка, шаги описывают приготовление.

Ручная покупка независима от плана; отметки «Куплено» переносятся только для неизменных товара и количества. Один список может иметь несколько магазинных ссылок по 30 разных товаров. Сохранение создаёт новую версию и обновляет ссылки.
