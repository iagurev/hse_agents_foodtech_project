# Продуктовые решения

Обновлено: 2026-10-19. Источник требований — [продукт и границы MVP](../design/product.md); этот файл служит кратким указателем.

- Пользователь свободно обсуждает питание, ищет рецепты, создаёт и меняет планы и корзины. Обязательный сценарный маршрут не вводится.
- Несколько чатов используют общую анкету и свободнотекстовую память. История и временные исключения остаются в своём чате. Память обновляется при явном устойчивом изменении, уточнении или исправлении после пересмотра пользователем; фоновой очистки нет.
- Маркировка КБЖУ, цены, физические единицы и время требуют подтверждения; неполные рецепты сохраняются для доработки. Позднее пользователь **разрешил новые граммовки и порции в явно помеченных авторских адаптациях**. Это состав нового блюда, а не измерение исходных ложек/штук. Товары ВкусВилла сохраняются в исходном MCP-формате. [Текущие правила](../technical/catalog-cleanup.md).
- По прямому поручению пользователя общие продукты строятся из товаров ВкусВилла на уровне «творог», «яблоко», «мука»: бренды, фасовки и жирность обычного творога объединяются. Существенные виды сырья и состояния разделены. КБЖУ и цены категории агрегируют подтверждённые наблюдения; неизвестные данные и коэффициенты не угадываются. Полные категории входят в рабочий поиск, неполные сохраняются для доработки. [Справочник](../technical/product-directory.md).
- Рецепты строятся от очищенных доступных категорий: допускаются кулинарно совместимые обобщения, исключение некритичных компонентов и новая рецептура. Основа и технологические вещества сохраняются; адаптация получает отдельный ID, согласованные шаги и новый расчёт. Состав/показатели карточки даны на одну базовую порцию, шаги — на явно указанную всю партию. [Правила](../technical/catalog-cleanup.md).
- После исчерпания лимита ключа пользователь выбрал завершение доступного набора офлайн. Публикуются прошедшие сохранённую кулинарную проверку и строгие офлайн-проверки варианты; неоднозначные рецепты и незавершённые предложения исправлений сохраняются для доработки.
- Собственная подготовленная база рецептов наполняется отдельно от обычных запросов. Карточки содержат данные выбора, фотографию и короткий текст ограничений; дополнительного уровня блюда и обязательного summary нет.
- Сложность учитывается наряду с составом, временем, техникой, КБЖУ и приблизительной стоимостью. Условие может поступить из анкеты, памяти или диалога.
- При создании агент передаёт ограничения явно. При редактировании сохраняются условия объекта, если пользователь явно не меняет их в поручении. Бюджет передаётся без прибавки, фиксированный допуск 5% применяет код; согласование погрешности не требуется. Целевые КБЖУ не выдумываются; кодовые проверки ограничены четырьмя согласованными критериями.
- Поиск рецептов, товаров и аналогов возвращает до 10 кандидатов без выбора размера агентом. Ингредиенты берутся из существующего справочника; новые записи в диалоге не создаются. Свободный список товаров агент превращает в выбор SKU через поиск товаров.
- Редактирование возвращает полную новую версию, сохраняя предыдущую. Незатронутые приёмы пищи, количества и выбранные SKU должны сохраняться.
- План и корзина — отдельные сохранённые объекты. Корзина создаётся из плана, рецептов или готовых SKU/упаковок. Поисковое уточнение применяется буквально к каждому ингредиенту, не меняет его количество; ссылка на корзину не оформляет заказ. Частичная корзина допускает конкретную заранее разрешённую замену без повторного согласия; одинаковые безрезультатные попытки не повторяются.
- Ориентир нагрузки — до пяти запросов пользователя в день, бюджет LLM — до $20 в месяц. Измерения небольшой серии доступны в техническом отчёте; они не устанавливают SLA для большого каталога.

Технические выборы находятся в [harness](../technical/agent-harness.md) и [контрактах](../technical/tool-contracts.md). Неутверждённые детали — в [открытых решениях](../technical/open-questions.md).

- Мобильный веб-интерфейс без рамки: Чат, Планы, Рецепты, Покупки; профиль из шапки. Рецепты только из актуальных планов, полный каталог ищется в чате.
- Логин 1–64 и непустой пароль. Бюджет один: 15–20/20–25/25–30/30–35/35–40/40–50 тысяч в месяц на человека либо без ограничений; пропуск не задаёт лимит. Для полного меню агент использует верхнюю границу /30 × дни, уточнения важнее анкеты.
- Ручные порции/удаления плана и упаковки/удаления покупки создают версии без LLM. «Куплено» — только отметка; самостоятельная покупка не изменяет план. Удаление чата не удаляет предметные объекты и память. [Мобильный продукт](../design/product.md#мобильное-приложение).

- По поручению пользователя в рабочем репозитории остаются только финальные наборы рецептов, продуктов и исходников. Черновики, резервные копии и разовая подготовка сохраняются во внешнем архиве рядом с репозиторием для будущей доработки. [Размещение](../technical/data-storage.md).

- По решению пользователя генератор получает все рецепты в компактной проекции с уникальными названиями ингредиентов без ID и без общих служебных примечаний. КБЖУ базовой порции рецепта округляются до целых, цены до копеек также в базе; точные исходные маркировки и дробные количества не меняются.
